# kteam web UI redesign

## Shipped experience

The daemon-served UI is now a full-width, client-rendered React SPA. One shared
fleet store owns the session cache and the single fleet WebSocket, applies event
deltas, reconciles periodically, and reconnects with backoff. Dashboard,
session, and new-session routes use `pushState`; mounted dashboard/chat panes
preserve their local scroll and draft state while the user navigates.

The shell has a persistent fleet sidebar on every route. It owns the shared
search, All/Auto/Interactive, Remote Control, and include-finished filters. It
is an expanded column on wide screens, a forced icon rail below 1100 px, and an
overlay drawer below 768 px. The dashboard reflects the same filter state and
uses a six-column, TASK-first table at wide sizes plus cards when narrow. A
leading bracketed task owner such as `[Hayden]` is rendered separately, while a
plain `config.name` remains readable unchanged.

Session chat keeps the transcript follow/detach and history-prepend invariants.
The header is now a compact identity summary with grouped Identity, Runtime,
Progress, and Budget details. The composer is one bordered input surface with a
stable model/turn/context/status strip and in-surface Send, Queue, and explicit
Interrupt & send controls. Enter follows the safe send-or-queue path,
Shift+Enter inserts a newline, structured questions replace the composer, sends
are synchronously locked, and retries reuse their idempotency identity.

Mobile uses the visual viewport as the shell's height source, with rAF-throttled
`resize` and `scroll` updates, `100dvh` fallback, Android
`interactive-widget=resizes-content`, and notch/home-indicator safe-area
padding. The document itself does not double-scroll; dashboard, drawer, and
transcript each retain their intended bounded scroller. Inputs are at least
16 px, coarse-pointer controls and rows have a 44 px floor, and every theme has
its own phone type ramp rather than inheriting desktop's dense chrome. The
transcript's pointer-latched detach and prepend gap-correction invariants remain
intact.

The phone chat route now uses one 49–52 px session row instead of separate app,
identity, and tab bars. It re-homes the drawer and theme controls, uses compact
icon tabs below 420 px, keeps waiting/needs-human state in a conditional strip
no taller than 24 px, and leaves desktop chrome unchanged. The touch composer
removes the hardware-keyboard hint, collapses context to its essential signal,
caps its textarea at 96 px normally and 64 px while the keyboard is open, and
keeps the full `Interrupt & send` wording and safety semantics. A six-line draft
scrolls inside the textarea instead of expanding the composer over the
transcript. Keyboard geometry never issues a transcript scroll intent, so an
upward-detached reader is not re-pinned when the keyboard opens or closes.

Android keyboard state is detected against the tallest uncovered height learned
for the current layout width, not an orientation label. That matters because
`screen.orientation.type` can lag a real rotation. Cross-width inference is
bounded and rejects ambiguous geometry to no baseline, which fails toward
keyboard-closed/full chrome. The detector therefore recovers through a focused
portrait → landscape/dismiss → portrait/reopen → portrait/restore sequence
without requiring the textarea to blur.

Five curated families ship in both light and dark modes: Studio, Mission
Control, Neo-Brutalism, Ember, and High Contrast. The picker has live previews,
explicit Auto/Light/Dark preferences, keyboard navigation, and persistence.
The pre-paint bootstrap in `ui/index.html` prevents a wrong-theme flash and the
font links no longer use a CSS `@import`.

## Theme token contract

There is exactly one resolved root attribute:

```html
<html data-theme="<family>-<mode>"></html>
```

`family` is `studio`, `mission`, `neo`, `ember`, or `contrast`; resolved `mode`
is `light` or `dark`. The preference stored under `localStorage['kteam-theme']`
is JSON shaped as `{ "family": string, "mode": "system" | "light" | "dark" }`.
When mode is `system`, the hook follows `prefers-color-scheme` live. The inline
bootstrap in `ui/index.html` and `src/hooks/useTheme.ts` intentionally implement
the same parsing/resolution rules and must be changed together. Legacy bare
`light`/`dark` values resolve to Studio.

Every family/mode selector also has a matching
`[data-swatch='<family>-<mode>']` selector. This lets the picker render genuine
nested previews without changing the page theme. Literal palette values belong
in `src/themes.css`; React components consume semantic Tailwind aliases or CSS
variables and must not introduce palette utilities or literal colours.

The required token groups are:

- Typography: body/display/UI/prose/mono families; the complete text ramp;
  normal/medium/strong/display weights; leading and tracking; label size,
  casing, variant, and weight; chrome ink/size; prose measure; input size.
- Geometry and stroke: radius ramps plus control/panel/badge/tab/input roles;
  control/panel stroke roles; divider rules; optional control/panel clips and
  HUD bracket size. Components consume role tokens, never raw ramps.
- Elevation: separate control/panel/popover/active shadows, press translation,
  active rail, inset rule, glow, and shadow ink. This is intentionally a
  different model per family: blurred Studio, glowing Mission, hard-offset Neo,
  paper-seam Ember, and outline-only High Contrast.
- Density: desktop control/row heights, mobile target floor, panel/row/cell
  padding, control/badge padding, and gap roles. Coarse pointers resolve every
  interactive target to at least 44 px without forcing desktop density.
- Surfaces and ink: page/surface levels, foreground hierarchy, decorative
  border levels, contrast-constrained `--border-strong`, accent/message/code
  surfaces, semantic state, tool, and syntax colours.
- Treatment and accessibility: panel texture/background, body wash, overlay,
  scrim, focus width/offset/colour/shadow, selection, and link-underlining
  behavior. `--accent-border` is decorative only; selected/pressed state uses
  contrast-constrained `--accent`.

Themes may change typography, geometry, borders, and shadow/effect models, not
only colours. Reduced-motion rules must suppress decorative animation and
scanline motion without removing information or focus indication.

The five family grammars are intentionally recognisable without colour:

- Studio uses mixed-case product typography, compact controls, soft radii, and
  blurred elevation.
- Mission Control uses mono UI text, condensed uppercase display labels,
  notched controls, hairline telemetry rules, grid/scanline treatment, signal
  rails, corner brackets, and inset/outer glow.
- Neo-Brutalism uses zero radius, 2–3 px ink strokes, heavy type, blocky
  controls, and hard offset shadows that physically depress when pressed.
- Ember uses serif transcript prose at a book measure, humanist UI text,
  small-caps labels, pill tabs/badges, broad spacing, warm paper seams, and the
  loosest reading rhythm.
- High Contrast uses the largest controls, heavy permanent outlines, no glow or
  decorative effects, always-underlined links, and a strict black/white
  instrument silhouette.

## Build and deployment safety

`ui/package.json` points the normal production build at `../ui-dist`, and
`kteamd` serves that directory directly from disk. Therefore **running
`bun run build` is an immediate live deployment**, even before the generated
files are reviewed or committed. It can expose a partial source migration to a
real user and must never be used as a routine verification command.

Use an explicit temporary Vite output for every development/review build, for
example:

```sh
bunx vite build --outDir /tmp/kteam-ui-review-<unique> --emptyOutDir
```

Only the designated release owner may run the normal build, once, after source,
contrast, interaction, mobile, and grayscale gates pass. That controlled build
must be followed immediately by inspection and a dedicated `ui-dist` deployment
commit. No daemon restart is required.

## Verification performed

- `bun run check`, the token contrast audit, and a production Vite build to an
  isolated temporary output directory pass. The audit measures 1,470 pairs
  across all ten themes: 0 hard failures, 178 explicitly decorative advisory
  rows, and 0 unresolved values. Neo light/dark hold their AA claim and High
  Contrast light/dark hold their AAA claim.
- The current dashboard entry is about 299 kB raw / 90 kB gzip, down from the
  837 kB / 254 kB baseline. Chat Markdown/highlighting is lazy, retained panes
  have independent Suspense boundaries, and all mounted consumers share one
  visibility-gated usage poll.
- The final browser interaction gate covers sidebar filters and scrolling, SPA
  navigation/back/forward, all ten theme variants, theme/drawer focus traps,
  safe Queue/Interrupt/Send paths, transcript upward detach without repinning,
  simulated keyboard viewport recovery, and 360x640, 390x844, 430x932, and
  844x390 layouts. It performed zero live mutations.
- Mobile density is a hard measured gate rather than a screenshot judgement.
  At 390x844 the five Light families leave 78.6–80.0% of the shell to the
  transcript, with a 98–105 px composer and a single 49–52 px header row. With a
  simulated 336 px keyboard and a six-line draft, they retain 61.4–63.2% content,
  a 312–321 px transcript, and a 118–124 px internally scrolling composer. All
  touch targets remain at least 44 px and the textarea remains 16 px. High
  Contrast also passes at 360 px with 61.4% content, a 312 px transcript, and a
  124 px composer. The mobile dashboard leaves 94.6% of the shell to its 798 px
  scroller and never scrolls the document.
- The phone exception strip is checked separately from the common send-ready
  fixture. Its measured heights are 18.89 px Studio, 17 px Mission Control,
  21.55 px Neo-Brutalism, 19.55 px Ember, and 22.19 px High Contrast; the words
  `parked:` and `needs human` remain available as applicable.
- The Android `resizes-content` gate keeps the textarea focused while opening,
  rotating/dismissing, reopening, and restoring. A first implementation failed
  because it keyed the read path on a stale orientation label; the gate caught
  that and the detector moved to width-keyed baselines. A later hardened harness
  also failed after its pre-document fake `visualViewport` froze impossible
  pre-meta geometry. Closure instrumentation identified the 390x2121 fixture
  value, the shim was corrected to follow live geometry until explicitly
  overridden, and the unchanged product then passed. A separate Chromium trace
  using the browser's native `VisualViewport` object (no shim) independently
  confirmed 844 px full → 508 px keyboard-open → 390 px rotated/full →
  508 px reopened → 844 px restored/closed.
- The screenshot matrix contains dashboard and chat in all ten resolved themes
  at 1440x900 and 390x844 (40 normal captures), plus ten desktop
  achromatopsia captures, under the batch scratchpad `shots/` directory. Human
  review confirmed that every family remains structurally recognisable without
  colour. Mission Control's six-column 1440 px table has zero overflow.
- The grayscale gate was not a rubber stamp: its first review rejected Mission
  Control Light as too close to Studio, and that pass was explicitly withdrawn.
  One bounded correction replaced the invisible light wash with a ruled
  telemetry field, squared the chassis, strengthened rules/insets, and enlarged
  control chamfers; the recapture is unmistakable without hue. The first
  screenshot harness also changed `data-theme` behind React's back, leaving the
  picker label stale. The final harness drives the real family/mode buttons and
  requires trigger label, resolved attribute, and stored preference to agree for
  every capture.
- The daemon serves the committed `ui-dist` directly at
  `http://127.0.0.1:7337/`; no daemon restart is part of deployment.
- Separately from this UI deployment, `kteamd` still needs a user/lead-owned
  restart before two already-landed daemon-side changes take effect: the chat
  pointer self-heal and the `--teammate`/session-name fixes. This UI batch did
  not restart the daemon because that operational decision is outside its
  ownership.

## Known debts and deliberate cuts

This is the review queue, not a claim that each item is equally urgent:

- Physical iOS Safari and Android Chrome devices were not available. Automated
  touch, `visualViewport`, keyboard-pan, safe-area, and rotation checks pass,
  but the final software-keyboard behavior still needs one physical-device
  smoke on each platform.
- Browser text-only 200% zoom remains a manual check. The automated CDP 200%
  page-scale run is a useful overflow/composer smoke, but it is not equivalent
  to text-only zoom.
- Some decorative hairlines, badge edges, pale accent tints, and focus blooms
  remain below 3:1 by design. They never carry a control boundary, state, or
  focus indication alone; the contrast audit keeps all 178 rows visible as
  advisory rather than suppressing them. The real control edge, state ink, and
  focus outline are contrast-constrained separately.
- Disabled controls still use `opacity: 0.55`; a later pass could give disabled
  ink/surface explicit tokens if visual testing finds them too faint.
- The dashboard switches table/cards from viewport width, not the main pane's
  container width. A manually expanded sidebar can therefore squeeze the table
  before the breakpoint changes.
- Checkbox styling remains global and may make compact checkboxes look larger
  than their surrounding sidebar chrome.
- `--user-rail` is still declared in all ten theme blocks but currently has no
  consumer. It should either be removed or adopted in a deliberate message-rail
  treatment instead of lingering as a dead token.
- Long transcript virtualization was deliberately cut: it risks the verified
  follow/detach and prepend-correction behavior and should only be attempted
  after profiling a representative large transcript.
- Reconnect recovery is automatic and quiet. The browser smoke test exercises a
  live WebSocket but does not comprehensively force a long outage/reopen;
  multi-minute outages, daemon replacement, and offline mobile resume remain
  better candidates for a dedicated resilience suite.
- No new UI dependency, rich command palette, animated route transition, or
  configurable dashboard column system was added. These were cut to keep the
  shipped interaction model small and dependable.

The legacy Studio faint/muted text contrast issue is resolved and is **not** a
remaining debt. The mobile drawer and theme picker now both trap focus and
restore it to their openers; the old missing-trap note is likewise closed.
